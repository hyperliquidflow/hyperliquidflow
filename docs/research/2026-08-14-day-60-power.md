# The day-60 checkpoint cannot decide anything, in either direction

Audit item 6 of [LESSONS.md](LESSONS.md), closed. The forward record's day-60
checkpoint was powered off a number that is now dead, and redone on the number
that is still standing it has **16% power**.

Arithmetic only, no new data. `lib/power.ts`, run 2026-08-14 at commit `b80da31`.

## What the checkpoint was built on

Amendment 3 set day 60 as a powered checkpoint on the positioning factor's
diagnostic at a bar of t 1.5, calling it 82% power. That was computed from the
diagnostic as it read on 2026-08-12: **t 3.17 over 104 days**.

The 200-day frozen extension replaced that reading with **t 0.70 over 107 days**
([2026-08-13-200d-frozen-extension.md](2026-08-13-200d-frozen-extension.md)). The
checkpoint's arithmetic was never redone, so a schedule built on a dead number is
still standing and still due around 2026-10-11.

## The consequence, which is not a kill

**Day 60 is uninformative in both directions and must not be read as a verdict.**

A failure to clear the bar is not evidence against the factor, because the
instrument would fail 84% of the time even if the effect were exactly as strong
as measured. A pass would be more likely noise than confirmation, since clearing
1.5 from an expected 0.52 takes a favourable draw.

This is the same defect Amendment 3 was written to fix, reappearing because the
input changed and the arithmetic did not. A power calculation is not a one-time
ceremony; it is a function of an estimate, and it expires when the estimate does.

**What to do with the record.** Keep it running. `factor-shadow.ts` costs nothing,
never backfills, and each row carries its own timestamps, so accrual is free and
a longer record is strictly better than a shorter one. What is retired is the
**decision** attached to day 60, not the recording.

**What would revive a decision point.** Not more days on this factor: 3.3 years is
not a plan. Only a materially stronger instrument would, and it would need its own
pre-registration and its own power calculation written before its data existed.

## The general form

Every scheduled gate in this repo inherits the estimate it was powered from. When
a run changes that estimate, the gates downstream of it are stale until their
arithmetic is redone. The 60-day bar has now been wrong twice for the same
reason, once too strict at 34% power and once too optimistic at an assumed 82%
that is really 16%.
